## 场景背景

一个开源紫微斗数项目（Next.js）排盘引擎完整，但**后端 AI 解读路由未开源**（README 明确说明「开源版不含 `/api/interpret`，需要你自己实现」），且商业版的「13 主题断语库、上万行」与解读 prompt 均闭源，`db-analysis.ts` 中的 `STAR_DB` 是空对象。

目标：在不复制断语库的前提下，让模型给出可用的解读。

## 核心结论：注入结构化数据，而不是注入断语

**做法**：把命盘对象全量转成结构化文本喂给模型，而不是让它背断语。

注入内容（`chart-text.ts`）：

- 命籍信息：出生时间、性别、阴阳、五行局
- 命局：命宫、身宫落点
- 十二宫：每宫主星 + **亮度（庙旺利陷）+ 四化 + 宫干自化 + 借星**
- 大限序列：各限区间、宫位、大限四化

**效果对比**：

| 方式 | 结果 |
| --- | --- |
| 靠模型记忆断语 | 泛泛而谈、套话，无法对应具体盘面 |
| 全量注入结构化数据 + 判断规则 | 输出能与盘面逐项对应（命宫贪狼旺守子、身宫落夫妻宫廉贞天府、大限三方会照官禄七杀地劫），可核验 |

数据许可提示：断语库本身受非商用条款约束，绕过它既有工程原因也有合规原因（见「数据许可与内容合规红线」）。

## 系统提示词的三层结构

1. **角色与体系**：明确以特定流派（本例为倪海厦体系）为判断框架，避免模型自行混合流派导致口径不一。
2. **判断规则**：把体系中的关键推理规则写成显式条目——三方四正如何会照、四化飞星如何作用、宫干自化如何读、空宫如何借星。规则让模型「按方法推理」而非「凭语感组句」。
3. **输出约束（OUTPUT\_RULES）**：独立成节，便于单独迭代。

提示词实测长度约 1389 字——足够表达规则，又不至于挤占盘面数据的上下文预算。

## 输出格式约束必须跟渲染层能力对齐

实测踩坑：模型默认输出 Markdown（`**加粗**`、`#` 标题），而前端面板按纯文本渲染，界面上会直接出现一排星号。

**规则**：输出约束由渲染层的实际渲染能力决定，不由「希望内容好看」决定。

- 纯文本渲染 → 明确禁止 `**`、`#`、列表符号，改用【】做段落分隔（如【命格定调】【当前大限 36-45 田宅】）
- 支持 Markdown 的渲染层 → 再放开格式

这条约束写在 `OUTPUT_RULES` 里，改完热更新即生效，无需改前端。

## 流式接口与提示词的配合

- 接口：`POST /api/interpret`，请求体 `{chart, messages}`，响应为 SSE，逐行 `data: {"delta":{"text":"..."}}`，以 `[DONE]` 结尾。
- 提示词设计要假设**流式**：首段必须能独立成句（用户先看到的是前 20 字），避免"综上所述""首先"这类必须依赖下文的开头。
- 前端零改动即可接入——它本来就在等这两个路由（`/api/interpret`、`/api/heming`）。

## 已知局限（须写进产品预期）

- 格局判断、四化影响、大限走势这类**基于数据推理**的内容质量较好。
- 具体到某颗星的**古籍原话式断语**偏弱，属于模型自行组织的语言——这是因为断语库闭源，不是 prompt 能弥补的部分。
- 改进路径：积累用户反馈案例做 few-shot，逐步弥补；对应「04 数据集与评测」的案例沉淀。

## 可复用清单

1. 数据优先于语料：能结构化的领域数据全量注入，胜过让模型背结论。
2. 判断规则显式写：把领域方法论翻译成条目，避免模型用通用语感替代专业推理。
3. 输出格式由渲染层倒推，写死在独立规则块里。
4. 提示词要为流式输出设计段落级可读性。
5. 明确写出「模型做不到的部分」，避免用户用商业版预期衡量开源实现。

## 六、「独立第二意见」的 prompt 设计与审计假阳性（2026-11-03 新增）

### 场景

让外部 LLM（DeepSeek）做「方法论独立的第二意见」时，最大的敌人不是它答错，而是**伪独立**——它被喂了主模型的路径（xG、泊松、市场赔率），输出自然趋同，事后无法区分「两个模型都看到了」与「一个模型被另一个锚定」。

### 解法：prompt 主动「自废武功」

给独立第二意见的材料，必须先把主模型的路径堵死：

1. **数据段只给与主模型路径无关的原始事实**：进球/失球、主客拆分、近 5 场比分——一个 xG 数字都不给。
2. **明令禁止主模型的方法**：禁 xG、禁泊松（含双变量泊松、Dixon-Coles 等变体，防止换名绕过）。
3. **不给市场赔率**：防止锚定市场价（实测 codex 在可联网时全篇唯一数字就是市场去水值）。
4. **强制自报 **`method_used`** 字段**：让模型自己声明用了什么路径，供审计比对。

### 审计端的假阳性踩坑（重要）

为独立输出配了自动化审计（扫描其输出有无偷用主模型路径、λ 是否与概率自洽、概率和是否为 1）。首跑即出假阳性：

- **禁令原话被当成污染**：prompt 里写了「禁止使用 xG、泊松」，污染扫描把这句**禁令本身**命中为「使用了泊松」。弱预言检测同样命中禁令原话。
- **修正**：污染扫描只扫模型的**实际陈述**（跳过 prompt 文本本身）；弱预言检测只看模型给出的预言字段，不扫全文。

**通用规则**：凡是在 prompt 里写「不要做 X」的约束，下游任何对 X 的检测都必须先排除 prompt 文本，否则禁令越显眼、假阳性越稳定。

### 输出格式的固定化（用户消费侧约束）

高频重复任务（每场赛事预测）确定固定输出模板后，沉淀为长期规则而不是每次口头约定：

> 每场输出：方向（胜平负）1–2 个 + 让球推荐 1 个 + 比分 2 个，逐项标注信心等级（高/中/低）。

**规则**：用户确认过的输出格式应写入记忆/规则库，之后同类任务直接按模板输出，不再重新协商格式。

## 七、决策栏与建模栏分离：模板必须容纳「模型吃不下」的信息（2026-11-05 新增）

### 事故

11-05 欧冠核销时用户提出明确批评：布鲁日边锋特雷索尔迪连场破门、状态火热，赛前情报里存在，但**没有出现在预测输出里**——因为它不进入 λ 参数。该场他 25' 首开纪录，正是剧本的开场。

用户的表述值得原样保留：**「你别管你的模型怎么算，这种有价值的信息你肯定是要列出来的。」**

### 根因：把「模型需要的输入」当成了「用户需要的输出」

建模管线的输出被 λ 与概率矩阵垄断，凡不能被泊松消化的信息在汇总环节被静默丢弃。但用户的决策链路与模型的估计链路不是同一条：

| 层 | 需要什么 | 谁消费 |
| --- | --- | --- |
| 建模层 | 可参数化的量：λ、伤停净效应、主客场系数 | 模型 |
| 决策层 | 人名、状态、动机、对位、教练倾向、赛程权重 | 用户 |

**原则：决策所需信息 ⊇ 建模所需信息。** 不能被模型消化的信息不是噪声，它只是不进概率，仍必须出现在输出里。这条原则对任何「模型 + 人工决策」的产品都成立：**输出的丰富度由用户的下游动作决定，不由模型的可解析性决定。**

### 固定模板新增「重点球员」栏

> 每场固定输出模板在「方向 / 让球 / 比分 / 信心」之外新增「重点球员」栏，与方向表同级、不许省略。入选条件（满足任一）：
>
> 1. 近 3 场参与进球 ≥3；
> 2. 连场破门（≥2 场）；
> 3. 刚复出或刚伤愈的核心球员；
> 4. 对方防线的最直接对位威胁（快马 vs 慢中卫等）。

书写要求：**人名 + 球队 + 一句可核验的状态事实**（如「连续 3 场欧联破门，右路持球内切」），不写空泛评价。若一场确无满足条件者，写「无」而不是删除该栏——**栏位存在本身就是约束**，删栏等于给下一次偷工留口子。

### 附带的投入分级

同日确立任务分级，并与输出详略绑定：

- **主战场**（欧冠 + 五大联赛）：全流程——双源独立建模、盘口数票、重点球员清单、战术模拟按需。
- **娱乐盘**（欧联杯等）：轻流程——单模型 + 情报核对，不做深度核验。

分级的意义在于避免两件事同时发生：对低价值场次过度投入，以及在高价值场次偷工。

### 通用化：模板的三类栏目

由此归纳，固定输出模板应显式区分三类栏目，缺一类就会出现本次的问题：

1. **结论栏**（方向/比分/信心）：模型直接产出；
2. **决策栏**（重点球员、战意、轮换、临场变量）：模型只负责检索与陈述，不要求可参数化；
3. **可证伪栏**（预言与证伪条件）：供赛后归因。

多数模板只设计了第 1 类，第 2 类被当作「模型算不进去所以不写」——这正是本次事故的机制。

## 八、受众分层输出：「推荐话语」与「诚实备注」分开（2026-11-06 新增）

### 场景

用户已自选两注（威尼斯负、塞维利亚胜），要求「再抓一下数据 + 给我推荐话语；方向若有变，提醒我」。

这是首次出现**输出要被二次使用**的需求：用户要把其中一段直接转发给别人。原有单一结构（方向表 + 概率 + 风险）无法直接满足——把 EV 和 Brier 发给朋友没有意义，把叙事写成学术段落又没人愿意看。

### 模板：三层分离

| 层 | 内容 | 受众 | 硬约束 |
| --- | --- | --- | --- |
| ① 对外推荐语 | 一句判断 + 3–5 条可核验事实 + 盘口动向 + 一句结论式口径 | 第三方 | 不出现概率、EV、Brier、模型名；每条事实须能被公开资料核到 |
| ② 对内诚实备注 | 模型概率 / 竞彩去水概率 / EV 三列表 + 单注最大风险 | 用户本人 | 必须写出「这注最大的敌人是什么」 |
| ③ 方向变更提示 | 有变 → 置顶说清变在哪一条；无变 → 明确写「方向不变，但信心 X」 | 用户 | 不允许用「基本维持」含糊 |

对外段的实际写法（可直接转发）：

> **威尼斯 负**（vs 乌迪内斯）——倒数第一打倒数第二，但两边的「烂」不一样：威尼斯 10 轮 3 分、三连败且 221 分钟没进过球；乌迪内斯刚换帅，新帅正是当年带威尼斯升上意甲的功勋教练，首秀战旧主，后防大将复出。盘口也在动：主胜赔率全面走高，资金在撤离威尼斯。**这场信换帅反弹，不信主场。**

### 三条写法要求

1. **对外语必须先说共识、再拆共识**。「倒数第一打倒数第二」是市场共识，紧接着一句「但两边的烂不一样」把分歧点亮——直接给结论而不先说共识，读者无法判断这句话的信息量在哪。
2. **对内备注必须落到赛果形态**。「有风险」无用；「这场最大的敌人是平局，1-1 就死，平局概率接近三成，仓位别重」才有决策价值。
3. **方向不变也要交代信心的变化**。塞维利亚场方向维持，但罗梅罗存疑 + 交锋史反向使信心下调；只报「方向不变」会隐藏信息量的损失。

### 为什么值得单独成节

这是第七节「决策栏 ⊇ 建模栏」的延伸：输出结构由下游动作决定，而**下游动作不止一个**。用户既要拿它下注（需要概率与 EV），也要拿它转述（需要叙事与盘口）。一份输出同时服务两个动作时必须显式分层，否则必然在其中一端失真——要么对外泄漏了不该给的赔率判断，要么对内省掉了关键的失败概率。

### 通用化

任何「分析 → 决策 → 转述」的链路都适用：先问「这份输出会被谁、在什么场景下二次使用」，再决定分几层。分层的判据不是内容多少，而是**同一段文字是否存在互相冲突的使用场景**。存在冲突就必须拆，拆的依据是受众而非篇幅。

## 九、「模拟」类输出的形态约束：教练视角推演与战术板动画（2026-11-08 新增）

用户当日明确否定了此前的战术模拟交付形态：「我让你模拟是真的模拟，不是给我放几个数据。」据此重新定义该类输出的最小完备结构。

### 定义：什么才算「模拟」

战术模拟不是概率表的另一种排版，而是**双方主教练视角的约束推演**：各自的处境 → 由此决定的排兵约束 → 首发与替补 → 关键对位 → 时间线剧本 → 比分。数据只作约束条件输入，不作结论输出。

反例（不达标）：罗列 λ、xG、控球率后直接给比分。
正例（达标）：先说「卡里克必须赢，所以不能收缩，代价是双后腰只能用两名组织型，等于用中场屏障换进攻」，再由这个约束推出剧本「先得分，然后守不住」。

### 结构模板

| 段落 | 必含内容 |
| --- | --- |
| ① 双方处境 | 教练压力、赛程密度、伤停名单、必须赢/可以接受平局的处境差 |
| ② 排兵约束 | 由处境倒推的硬约束（哪些位置无人可用、哪个取舍无法回避） |
| ③ 首发与替补 | 完整 11 人 + 关键替补，**每条附理由**，并标注确认度 |
| ④ 胜负手 | 「漏洞对漏洞」的对位分析，指出最可能爆的单点 |
| ⑤ 剧本与比分 | 分时段叙事（0–30′ / 30–60′ / 60′+）+ 主推比分 + 备选比分 |

### 三个强制标注

1. **唯一变量**：把「能改变比分的那个不确定项」显式标出并给概率。例：万-比萨卡赛前评估（60% 出场）→ 出场则 1-1/1-2，缺阵则曼联左路被打穿、1-0/2-1 权重上升。
2. **口径来源**：首发为「四家媒体预测口径汇总」，非官方名单；临场 60 分钟 confirmed XI 公布后需说明如何调整 λ（本例：万-比萨卡确认缺阵 → 曼联 λ 上调、维拉下调）。
3. **结论与方向表的一致性**：当个人判断比发布值更激进时须明说。例：方向表给「胜/平」是跟市场，但私下判断偏维拉——分歧场必须让用户看见分歧本身，而不是藏在混合权重里。

### 战术板动画的交付规格

将上述推演转成可播放的可视化时，采用以下规格（已验证可交付、可直接外发）：

- **单文件 HTML，零外部依赖**：CSS/JS 内联，无 CDN、无图片外链，发给任何人双击即开；
- **分阶段推进**：12 个阶段，每段 2.5 秒自动推进，含播放控制；
- **三要素同屏**：时间线、场上球员位置（按阵型坐标布点）、比分牌；比分牌随阶段联动更新；
- **文案与数据同源**：动画中的球员名、比分、事件时间必须与文字推演完全一致，且**生成后做一次全文人名核验**（本例检查错误归属球员出现次数为 0）。

### 数据严谨性五条硬标准

由「恩佐归属」事故直接催生，适用于所有输出（含动画、海报、报告）：

1. 球员所属球队、教练归属必须核对**当期**状态，不采信跨窗旧记忆；
2. 无可靠出处的内容**整句删除**，不用「据悉/大概」等模糊说法带过；
3. 译名统一用主流中文源标准译名；
4. 数据口径必须标注（联赛 / 各项赛事、初盘 / 临场、去水前 / 去水后）；
5. 交付前做一次**人名归属自检**（逐个球员核对现属球队），作为发布前固定检查项。

> 与《偏差清单》第十四节的关系：那一节讲「为什么会错」，本节讲「错了之后输出形态该怎么定」。两条合起来构成一条纪律——**没有核实过的数据宁可不出现**。

## 十、反同质化审计 prompt：方法论隔离与自证伪字段（2026-11-15 新增）

**问题**：双审计的目的是拿到「独立的第二意见」。若审计模型使用与本管线相同的方法（λ + 泊松 + 市场去水），它只会复现同一套误差，形成同质化假一致——看起来三方吻合并不能证明判断正确，只能证明方法相同（参见第六节的假阳性讨论）。

**四条设计（把「独立性」从口头要求变成可检查的字段）**

1. **方法论隔离（禁令式）**：明确禁止使用 xG 与任何进球分布模型（泊松、双变量泊松、Dixon-Coles），并指定替代依据清单——真实战绩与进失球、主客拆分、赛程密度与休息天数、伤停对阵容结构的影响、近期状态趋势、实力档位判断。禁令必须点名具体方法；只写「请独立判断」等于没写。
2. **方法自报**：method\_used 字段限 50 字、要求具体到可核验。事后判定独立性靠这一栏，而不是靠模型的自我宣称；填「综合考虑各因素」的输出按未达标处理。
3. **输出形态约束**：三项概率为整数且和恒等于 100（小数位是伪精度）；confidence 三档；key\_factors 限定三条以内，强制取舍而非罗列。
4. **可证伪预言**：命中概率必须落在 40%\~60%，或给出明确阈值，并显式禁止「总进球不超过 3」这类覆盖 80% 以上区间的弱预言。

**第二路（取数型审计）另加五条硬要求**，把「取数质量」一并纳入审计：

- 必须自己联网取数，不许凭记忆；欧赔至少 10 家取中位；
- 不得把市场价填进自有概率字段，市场值另开 market\_p\_\* 字段供对比；
- 亚盘方向要「数票」：列全部机构当前盘口取众数，不看单家网站的初盘到当前路径；
- λ 禁止给完全对称值；若确实对称，须用市场去水概率反推等价实力差自证；
- 每个关键事实进 key\_facts 并附来源（URL 或数据集名），抓不到写 UNVERIFIED 并降 confidence。

**最有价值的产出是自证伪声明**：克罗地亚场 codex 主动写下「未取得所有机构当前亚盘，无法数票取众数，以下为未校准基线，不能视为完成要求的正式模型」并置 UNVERIFIED。这条自报比它的数字更可信，也直接决定采信方式——只做事实源，不做概率源。**采信门槛应按自报达标情况分级，而不是按模型名或历史准确率分级。**

\*配套要求：market\_p 必须同时写取样机构与家数。同一场西班牙-英格兰，我方欧洲 15 家中位去水 48.7 / 25.0 / 26.3，codex 独立取样得 54.0 / 23.3 / 22.7，差 5.3pp——差异来自取样集合不同（含亚洲盘与竞彩口径），不是模型分歧。不写取样口径的「市场值」不可用于判定裂缝。

### 可复用清单

- 三条禁令 + method\_used + 概率和 100 + 可证伪预言 + key\_facts 带来源，构成最小可用的反同质化审计模板。
- 要求对方「用不同方法算同一个问题」，而不是「再算一遍」。
- 把「自报未达标即降级为事实源」写进流程，避免把未校准数字混进概率池。

## 十一、对抗式审计 prompt 的「禁输出概率数字」边界（2026-11-19 新增）

**背景**：胜负彩 26166 期建模引入外部审计时，在第十节「反同质化审计 prompt」基础上追加了一条显式边界：**审计员只做事实核验与遗漏检查，禁止输出自己的概率数字、禁止替建模方下最终结论，发布值不接受外部数字集成**。

**要点**：

1. **责任链单一**：发布值由建模方全责。外部模型一旦输出概率数字，就存在「取平均/取中位」的诱惑，而这正是 11-16 已验证的失效模式（动机不对称场次外部审计集体反向，权重记 0）。把「禁输出数字」写进 prompt，从源头堵死数字混入。
2. **能力上限显式声明**：prompt 开头要求审计员声明自身口径（deepseek 主动声明「无法联网、知识截止 2024-06，查不到就写查不到，不编 URL」），有效抑制幻觉式「核验」。审计报告因此天然分成「概念判断成立 / 算术成立 / 具体记录未查到」三档，可信度分级清晰。
3. **效果验证**：本次 deepseek 输出全部为事实核验表与系统性偏差挑战（双重计数、同场证据打架、可能性当确认），无一数字集成；同时抓出了建模方方案生成函数的真实 bug。边界声明没有削弱审计价值，反而让挑战更聚焦。
4. **配套纪律**：审计结论「站得住的落实、存疑的标注、错误的不采」，落实情况回写建模材料，形成闭环。

## 十二、外部审计 agent 的事实层局限：无联网旧知识「纠错」与研究的独立核实（2026-11-21 新增）

外部审计在方法论层持续有效（deepseek 的「已证伪」措辞降级、「市场已定价」证据强度不足两项挑战均被采纳），但其事实层在本轮再次失效。两条纪律固化：

1. **无联网审计员用旧知识做「当期纠错」必错**：deepseek 自述系统日期 2026-06-29、无联网，把 2026-11 的当期信息当未来，用旧知识错称「瓜迪奥拉仍执教曼城」「恩佐在切尔西」「格伊在水晶宫」——其中「恩佐在切尔西」正是项目长期记忆记录过的历史错误，当场重复。当期归属（主帅、转会、阵中名单）必须以带时间戳来源核验，不能由断网模型裁决；对照实证：路透 11-20 报道切尔西主帅已换人、纳米 11-08 曼城 1-3 森林一役格伊与恩佐均在曼城阵中。
2. **外部 agent 给出的研究与归属必须独立核实**：本轮裁决引用的三项研究全部用独立检索核实为真实存在且数字对得上（见 01 第二十八节），同时抓出一处口径限制（Frontiers 为非洲杯长窗口征召）与一处转述错误（平局基准 32% 原文口径不同）。核实动作防的是「整条裁决建立在另一个 agent 的转述甚至幻觉上」。
3. **对抗式审计是双向的**：codex 联网审计不仅核我方结论，也推翻了我方当轮的「纠错」——门兴主场对多特近 6 次「4 胜 1 平 1 负」经 DFB 官方交锋档案确认成立，我据纳米明细改撤主胜上调反而是错的（纳米那组混入 2021 年德国杯，属「各项赛事」口径）。「近 N 次交锋」必须先钉死联赛/杯赛口径，「混口径等于造假」铁律对审计方与被审计方同样适用。
4. **事实层与方法论层分开记分**：同一份 deepseek 审计报告，方法论挑战采纳、事实层全否。在既有采信分级（概念成立/算术成立/记录未查到）之外再加一档纪律：涉及球员、主帅、归属的事实断言，一律须带时间戳来源复核后才可入库。

## 第十四节：四玩法赛果一致性——让球方向作锚（T10/T11）与「开始」触发词（2026-11-23 新增）

用户在 261123 期分析表发布后指出：005 场推荐让负(-1)，则 1X2 不可能是主胜、半全场不可能是胜胜/平胜。核查发现不止 005——003 让胜(+1)（主队不败）却给含客胜的 1X2 加半全场「平负/负负」（全场客胜），006 让负(-1) 却配「平胜/胜胜」（全场主胜），三场全部自相矛盾。

1. **根因**：胜平负、让球、进球数、半全场四个玩法各自独立取概率最高项，彼此没有赛果一致性约束，四列各取 max 拼在一行必然打架。
2. **规则（让球为锚）**：让球方向推导蕴含的 1X2 赛果集合，胜平负方向必须落在该集合内，半全场每一项的「全场结果」也必须落在该集合内。映射表：让胜(-1)与让平(-1)只允许主胜；让负(-1)只允许平或负；让胜(+1)允许胜或平；让平(+1)与让负(+1)只允许负；-2 线让负不约束（三结果皆可）。
3. **实现两条校验**：T10 检查让球与 1X2 的一致性；T11 检查半全场与让球蕴含集合的一致性。T11 的判据刻意不用 1X2 方向当基准——若 1X2 本身已错（T10 漏网），拿它当基准会让两个错互相掩护；直接对让球蕴含集合校验，锚只有一个。分析脚本直接 import 校验器的 hc\_implies 函数，规则单一来源。
4. **回测七例**：A 旧口径表拦 11 条、B 新规 0 条、C 市场 top1 当方向拦 3 条、D 缺市场对照栏拦 3 条、E 005 原稿拦 2 条（T10+T11）、F 003 原稿拦 2 条、G 让球锚定修正后 0 条。回溯检验昨日 261122 期判断表：12 条违规、6 场自相矛盾（011 最典型：1X2 给客胜却让胜(+1) 即主队不败，实际 3-2 主胜，等于让球中、1X2 输，自己跟自己打架）——证明这是长期流程缺陷，不是当日笔误。
5. **二串腿池一并修正**：原按发布值最高项取腿，出现过「蒙扎客胜」与自身方向（主队不败）冲突的候选腿；改为只从最终方向取腿（1X2 取方向列内符号、让球只取最终让球方向）。
6. **修正的边界**：一致性修正只改 1X2 与半全场，不动已定价的让球与二串票面（SP 2.558/2.852 未变）；每处剔除模型次优项的覆盖代价量化写进理由（003 覆盖 47.0% 降至 30.1%、005 44.9% 降至 34.2%、006 46.1% 降至 32.0%），不能悄悄换项。
7. **触发词规则**：用户明令，此后只发「开始」二字即等于「立刻预测当天竞彩开售的五大联赛、欧冠、欧国联比赛」，不反问、不等补场次；范围外联赛（瑞超、法乙、巴甲、美职、英冠、亚冠等）不列表，但须报告「本期竞彩共 X 场、其中目标赛事 Y 场」。规则载体分级照旧：代码优先于 notes，notes 优先于口头承诺，本条已写入两级长期记忆与校验器。

8. **出表校验清单**（`table_style_v2.py --check`，violations 为空才可发布）：T0 无行数据、T1 只三类赛事、T2 场次重复、T3 方向格式、T5 方向 ⊆ 让球蕴含集合、T6 总进球格式（3球 或 3球/4球）、T8 方向来源必须是 my\_publish / my\_analysis、T8v2 比分 ⊆ 方向、T8v3 比分净胜球 ⊆ 括号让球区间、T9 未开售不得进表、T11 半全场全场结果 ⊆ 方向。
9. **校验与渲染同源**：同一脚本提供 validate 与 render（html / md），一次出表即成型——蓝表头白字、红底为主推腿场次、红字为备选腿、黄底为★分歧场、底部黄条免责声明。样式常量与校验规则写在同一个文件里，避免「校验过了但排版退回旧版」。
10. **规则载体**：样式契约同时写入用户级长期记忆与工作区 §0，并落成代码校验，形成「口头承诺、notes、代码」三级中最强的一级；下次不依赖记忆，运行校验即拦。
11. **通用原则**：任何「方向 + 具体比分」同框出现的交付物，都必须有把比分映射回方向与盘口的机器校验；人眼校稿抓得住单行矛盾，抓不住四列联合约束。

## 第十六节：逐场「选择理由」的百字契约——表外位置、字数窗与四条硬校验（2026-11-25 新增）

用户要求「每场要给选择理由，一百字左右」，同时强调八列表一列都不许动。这一条把「长文本说明」与「结构化表格」的边界划清了。

1. **先问「占不占表」，再动手**：新增长文本需求时，第一件事是确认它是否进入表格契约。占表就要改列定义、改校验器、改渲染器；不占表就只改章节结构。本次判定为不占表，理由作为表外第二章挂在表格之后，八列的顺序与语义一字未动。
2. **字数窗设为 80 到 140 字**：下限防「一句话敷衍」，上限防「把表格和赔率再复述一遍」。实测 8 场 106 到 139 字、均值 118 字，全部落在窗内偏上——说明「一百字左右」实际应理解为「一百到一百二十字」，而不是八十。
3. **每条理由必须落到一个决策上**：至少要回答「为什么是这个方向、为什么是这个括号让球、为什么是这个比分」中的一项以上，并附一句反证（「但……」）。只写基本面背景、不写选择的，等于没写；写了选择但不给反证的，等于只报有利的一半。
4. **禁内部术语，改用大白话**：λ、DELTA、锚、Brier、去水、蕴含这类工作流内部词汇不得出现在理由正文里，写成「我算他平均能进两球」而不是「λ=2.0」。受众是转发出去的人，不是建模的自己；术语一出现，理由就从「解释」退化成「自证」。
5. **判断与数据的分离同样适用于理由**：理由里不许出现「市场给 60% 所以我也给」这类表述——那是数据不是判断。市场数字进表外附注并标口径，理由只写自己为什么这么选。这条与方向列必须来自 my\_publish 或 my\_analysis 是同一条原则的两个面。
6. **校验器 R0 到 R6**：把上述要求拆成机器可判的七条，其中四条核心项为「场次齐全、字数窗、禁内部术语、必须落到胜平负选择」，五个案例回测 PASS 才允许并入交付稿。规则只有落进校验器才算生效，写在说明里不算。
7. **校验器的正样本必须先过校验器**：首轮回测时被认定为「好案例」的样本文本自身只有 76 字，被自家下限 80 字拦下。规则上线前要用自己的正样本跑一遍，否则第一天就自相矛盾，用户看到的第一条报错来自规则本身。

## 第十七节：多模型群聊的发言 prompt 与角色防伪造（2026-11-25 新增）

把多个模型放进同一个对话框轮流发言，prompt 层的写法与单机问答差别很大；同一天里还发现，涉及「谁在说话」的部分，prompt 基本无能为力。

1. **群聊 prompt 不是单机 prompt 加一句「你们聊」**：必须显式写清两件事——「这是多人闲聊群」「其他人刚说过什么」，并明确禁止「复述上一位的观点」。不写这条，四家模型会互相复读、话题原地打转，一场十条消息里有效信息不到三条。
2. **同质化靠「切入角度」解决，不靠「人设形容词」**：给每个席位一个具体的切入角度（例如「从规则是谁定的角度切入」），比「你是一个犀利的人」有效得多。形容词不产生分歧，角度产生分歧；四个人设都写「独立思考」，输出照样趋同。
3. **角色隔离与防伪造必须落在代码层**：prompt 里写「不要冒充他人」没有任何约束力。做法是在适配器入口处做角色白名单（只允许真实模型角色走调用），手动席位一律抛 `manual_role`，即使演示模式开启也不会用预置句子顶替。判断标准是「关掉模型、看它会不会开口」——会开口就说明防伪造成了摆设。
4. **代笔必须标注来源**：第四席位由某个真实模型代笔时，消息带 `ghost` 字段、气泡标「代笔 · 模型名」，不冒充本人。可审计性优先于观感——用户要看到的是「谁在说」，不是「看起来像谁在说」。
5. **演示模式是显式降级，不是默认兜底**：未配置密钥时给明确错误或打「演示」标记，绝不伪造一段像样的回复。这条既是产品底线，也是提示词层的前提——一旦允许伪造，后面所有 prompt 调优都失去意义，因为无法分辨输出是模型给的还是模板给的。

## 第十八节：校验器的字面匹配误拦与措辞改写（2026-11-26 新增）

**现象**：`analysis_dims.py` 的 D4 校验（禁止把未证观点写成已证规律）按字面匹配拦下了「已证伪」「果然应验」两个词——即使正文整段语义是「对用户观点不下任何成立与否的断语」，只要字面出现触发词仍然违规。

**处置**：改写方式不是绕过校验器，而是把表述改成真正的中性断语——不出现「成立/不成立/已证实/已证伪/果然」这类判定词，只描述「该观点被登记为哪一层、需什么证据才能升级」。改后 D4 放行，全链路 8 道校验回归全绿。

**教训**：基于关键词的合规校验器会同时拦住「违规断言」与「讨论违规的元描述」。写正文时要避免出现触发词本身，而不是指望校验器理解语境；反过来，校验器升级也应区分「断言句」与「引用句」后再收紧，避免误伤。

**配套表述纪律**：判断层覆盖模型结论时必须写理由；「方向判断对了」与「事实层依据错了」分开表述（本期 003 双向事实纠错），不因结果正确掩盖过程错误，也不因过程错误否定结果。

## 第十九节 · 理由字数校验实战与收尾一致性顺序（2026-11-27 新增）

**一、reason 字数上限首次实战拦截**。五场初版理由 149至157 字，全部超出 140 字上限被 `reason_check.py --check` 拦下，两轮压缩至 132至138 字（均值 135）后全绿。压缩要点：删过程复述与铺垫，保留「为什么选这个方向或让球或比分」的因果与并列反证；先删背景、再删形容词、最后合并同义短句。

**二、多维稿护栏实战**。撰写时主动避开 D4 禁词（已证伪、果然应验、规律成立、确定是）；C 层 `preseason_intel` 五项全部标 media_question，sources 只登记 local_media 与 wire_service，pricing 不标 true——本期全程未获官方大名单或临场确认首发，聚合页预测首发按「登记不采信」处理。

**三、收尾一致性顺序教训**。v2 表 note 先写了「主推与备选已与二串同步」，但写 note 时 007 的 flag 仍为 null、二串文件尚未生成——声称同步必须发生在下游产物实际生成之后。正确顺序：先跑完二串脚本，再回填上游表格的 flag 与 note，最后重跑全量校验并渲染。任何「已同步」表述不得先于被同步对象存在。

**四、二串 SP 不硬编码**。SP 一律从落盘 data.json 读取，不在生成脚本里写死，避免竞彩调价后脚本输出与交付稿不一致；临场重抓时二串报价变化只登记（见 03 排障第三十二节），不回改已交付稿。
