# 结构化数据注入与输出格式约束

## 场景背景

一个开源紫微斗数项目（Next.js）排盘引擎完整，但**后端 AI 解读路由未开源**（README 明确说明「开源版不含 `/api/interpret`，需要你自己实现」），且商业版的「13 主题断语库、上万行」与解读 prompt 均闭源，`db-analysis.ts` 中的 `STAR_DB` 是空对象。

目标：在不复制断语库的前提下，让模型给出可用的解读。

## 核心结论：注入结构化数据，而不是注入断语

**做法**：把命盘对象全量转成结构化文本喂给模型，而不是让它背断语。

注入内容（`chart-text.ts`）：

- 命籍信息：出生时间、性别、阴阳、五行局
- 命局：命宫、身宫落点
- 十二宫：每宫主星 + **亮度（庙旺利陷）+ 四化 + 宫干自化 + 借星**
- 大限序列：各限区间、宫位、大限四化

**效果对比**：

| 方式 | 结果 |
| --- | --- |
| 靠模型记忆断语 | 泛泛而谈、套话，无法对应具体盘面 |
| 全量注入结构化数据 + 判断规则 | 输出能与盘面逐项对应（命宫贪狼旺守子、身宫落夫妻宫廉贞天府、大限三方会照官禄七杀地劫），可核验 |

数据许可提示：断语库本身受非商用条款约束，绕过它既有工程原因也有合规原因（见「数据许可与内容合规红线」）。

## 系统提示词的三层结构

1. **角色与体系**：明确以特定流派（本例为倪海厦体系）为判断框架，避免模型自行混合流派导致口径不一。
2. **判断规则**：把体系中的关键推理规则写成显式条目——三方四正如何会照、四化飞星如何作用、宫干自化如何读、空宫如何借星。规则让模型「按方法推理」而非「凭语感组句」。
3. **输出约束（OUTPUT_RULES）**：独立成节，便于单独迭代。

提示词实测长度约 1389 字——足够表达规则，又不至于挤占盘面数据的上下文预算。

## 输出格式约束必须跟渲染层能力对齐

实测踩坑：模型默认输出 Markdown（`**加粗**`、`#` 标题），而前端面板按纯文本渲染，界面上会直接出现一排星号。

**规则**：输出约束由渲染层的实际渲染能力决定，不由「希望内容好看」决定。

- 纯文本渲染 → 明确禁止 `**`、`#`、列表符号，改用【】做段落分隔（如【命格定调】【当前大限 36-45 田宅】）
- 支持 Markdown 的渲染层 → 再放开格式

这条约束写在 `OUTPUT_RULES` 里，改完热更新即生效，无需改前端。

## 流式接口与提示词的配合

- 接口：`POST /api/interpret`，请求体 `{chart, messages}`，响应为 SSE，逐行 `data: {"delta":{"text":"..."}}`，以 `[DONE]` 结尾。
- 提示词设计要假设**流式**：首段必须能独立成句（用户先看到的是前 20 字），避免"综上所述""首先"这类必须依赖下文的开头。
- 前端零改动即可接入——它本来就在等这两个路由（`/api/interpret`、`/api/heming`）。

## 已知局限（须写进产品预期）

- 格局判断、四化影响、大限走势这类**基于数据推理**的内容质量较好。
- 具体到某颗星的**古籍原话式断语**偏弱，属于模型自行组织的语言——这是因为断语库闭源，不是 prompt 能弥补的部分。
- 改进路径：积累用户反馈案例做 few-shot，逐步弥补；对应「04 数据集与评测」的案例沉淀。

## 可复用清单

1. 数据优先于语料：能结构化的领域数据全量注入，胜过让模型背结论。
2. 判断规则显式写：把领域方法论翻译成条目，避免模型用通用语感替代专业推理。
3. 输出格式由渲染层倒推，写死在独立规则块里。
4. 提示词要为流式输出设计段落级可读性。
5. 明确写出「模型做不到的部分」，避免用户用商业版预期衡量开源实现。

## 六、「独立第二意见」的 prompt 设计与审计假阳性（2026-11-03 新增）

### 场景

让外部 LLM（DeepSeek）做「方法论独立的第二意见」时，最大的敌人不是它答错，而是**伪独立**——它被喂了主模型的路径（xG、泊松、市场赔率），输出自然趋同，事后无法区分「两个模型都看到了」与「一个模型被另一个锚定」。

### 解法：prompt 主动「自废武功」

给独立第二意见的材料，必须先把主模型的路径堵死：

1. **数据段只给与主模型路径无关的原始事实**：进球/失球、主客拆分、近 5 场比分——一个 xG 数字都不给。
2. **明令禁止主模型的方法**：禁 xG、禁泊松（含双变量泊松、Dixon-Coles 等变体，防止换名绕过）。
3. **不给市场赔率**：防止锚定市场价（实测 codex 在可联网时全篇唯一数字就是市场去水值）。
4. **强制自报 `method_used` 字段**：让模型自己声明用了什么路径，供审计比对。

### 审计端的假阳性踩坑（重要）

为独立输出配了自动化审计（扫描其输出有无偷用主模型路径、λ 是否与概率自洽、概率和是否为 1）。首跑即出假阳性：

- **禁令原话被当成污染**：prompt 里写了「禁止使用 xG、泊松」，污染扫描把这句**禁令本身**命中为「使用了泊松」。弱预言检测同样命中禁令原话。
- **修正**：污染扫描只扫模型的**实际陈述**（跳过 prompt 文本本身）；弱预言检测只看模型给出的预言字段，不扫全文。

**通用规则**：凡是在 prompt 里写「不要做 X」的约束，下游任何对 X 的检测都必须先排除 prompt 文本，否则禁令越显眼、假阳性越稳定。

### 输出格式的固定化（用户消费侧约束）

高频重复任务（每场赛事预测）确定固定输出模板后，沉淀为长期规则而不是每次口头约定：

> 每场输出：方向（胜平负）1–2 个 + 让球推荐 1 个 + 比分 2 个，逐项标注信心等级（高/中/低）。

**规则**：用户确认过的输出格式应写入记忆/规则库，之后同类任务直接按模板输出，不再重新协商格式。

## 七、决策栏与建模栏分离：模板必须容纳「模型吃不下」的信息（2026-11-05 新增）

### 事故

11-05 欧冠核销时用户提出明确批评：布鲁日边锋特雷索尔迪连场破门、状态火热，赛前情报里存在，但**没有出现在预测输出里**——因为它不进入 λ 参数。该场他 25' 首开纪录，正是剧本的开场。

用户的表述值得原样保留：**「你别管你的模型怎么算，这种有价值的信息你肯定是要列出来的。」**

### 根因：把「模型需要的输入」当成了「用户需要的输出」

建模管线的输出被 λ 与概率矩阵垄断，凡不能被泊松消化的信息在汇总环节被静默丢弃。但用户的决策链路与模型的估计链路不是同一条：

| 层 | 需要什么 | 谁消费 |
| --- | --- | --- |
| 建模层 | 可参数化的量：λ、伤停净效应、主客场系数 | 模型 |
| 决策层 | 人名、状态、动机、对位、教练倾向、赛程权重 | 用户 |

**原则：决策所需信息 ⊇ 建模所需信息。** 不能被模型消化的信息不是噪声，它只是不进概率，仍必须出现在输出里。这条原则对任何「模型 + 人工决策」的产品都成立：**输出的丰富度由用户的下游动作决定，不由模型的可解析性决定。**

### 固定模板新增「重点球员」栏

> 每场固定输出模板在「方向 / 让球 / 比分 / 信心」之外新增「重点球员」栏，与方向表同级、不许省略。入选条件（满足任一）：
> 1. 近 3 场参与进球 ≥3；
> 2. 连场破门（≥2 场）；
> 3. 刚复出或刚伤愈的核心球员；
> 4. 对方防线的最直接对位威胁（快马 vs 慢中卫等）。

书写要求：**人名 + 球队 + 一句可核验的状态事实**（如「连续 3 场欧联破门，右路持球内切」），不写空泛评价。若一场确无满足条件者，写「无」而不是删除该栏——**栏位存在本身就是约束**，删栏等于给下一次偷工留口子。

### 附带的投入分级

同日确立任务分级，并与输出详略绑定：

- **主战场**（欧冠 + 五大联赛）：全流程——双源独立建模、盘口数票、重点球员清单、战术模拟按需。
- **娱乐盘**（欧联杯等）：轻流程——单模型 + 情报核对，不做深度核验。

分级的意义在于避免两件事同时发生：对低价值场次过度投入，以及在高价值场次偷工。

### 通用化：模板的三类栏目

由此归纳，固定输出模板应显式区分三类栏目，缺一类就会出现本次的问题：

1. **结论栏**（方向/比分/信心）：模型直接产出；
2. **决策栏**（重点球员、战意、轮换、临场变量）：模型只负责检索与陈述，不要求可参数化；
3. **可证伪栏**（预言与证伪条件）：供赛后归因。

多数模板只设计了第 1 类，第 2 类被当作「模型算不进去所以不写」——这正是本次事故的机制。

## 八、受众分层输出：「推荐话语」与「诚实备注」分开（2026-11-06 新增）

### 场景

用户已自选两注（威尼斯负、塞维利亚胜），要求「再抓一下数据 + 给我推荐话语；方向若有变，提醒我」。

这是首次出现**输出要被二次使用**的需求：用户要把其中一段直接转发给别人。原有单一结构（方向表 + 概率 + 风险）无法直接满足——把 EV 和 Brier 发给朋友没有意义，把叙事写成学术段落又没人愿意看。

### 模板：三层分离

| 层 | 内容 | 受众 | 硬约束 |
| --- | --- | --- | --- |
| ① 对外推荐语 | 一句判断 + 3–5 条可核验事实 + 盘口动向 + 一句结论式口径 | 第三方 | 不出现概率、EV、Brier、模型名；每条事实须能被公开资料核到 |
| ② 对内诚实备注 | 模型概率 / 竞彩去水概率 / EV 三列表 + 单注最大风险 | 用户本人 | 必须写出「这注最大的敌人是什么」 |
| ③ 方向变更提示 | 有变 → 置顶说清变在哪一条；无变 → 明确写「方向不变，但信心 X」 | 用户 | 不允许用「基本维持」含糊 |

对外段的实际写法（可直接转发）：

> **威尼斯 负**（vs 乌迪内斯）——倒数第一打倒数第二，但两边的「烂」不一样：威尼斯 10 轮 3 分、三连败且 221 分钟没进过球；乌迪内斯刚换帅，新帅正是当年带威尼斯升上意甲的功勋教练，首秀战旧主，后防大将复出。盘口也在动：主胜赔率全面走高，资金在撤离威尼斯。**这场信换帅反弹，不信主场。**

### 三条写法要求

1. **对外语必须先说共识、再拆共识**。「倒数第一打倒数第二」是市场共识，紧接着一句「但两边的烂不一样」把分歧点亮——直接给结论而不先说共识，读者无法判断这句话的信息量在哪。
2. **对内备注必须落到赛果形态**。「有风险」无用；「这场最大的敌人是平局，1-1 就死，平局概率接近三成，仓位别重」才有决策价值。
3. **方向不变也要交代信心的变化**。塞维利亚场方向维持，但罗梅罗存疑 + 交锋史反向使信心下调；只报「方向不变」会隐藏信息量的损失。

### 为什么值得单独成节

这是第七节「决策栏 ⊇ 建模栏」的延伸：输出结构由下游动作决定，而**下游动作不止一个**。用户既要拿它下注（需要概率与 EV），也要拿它转述（需要叙事与盘口）。一份输出同时服务两个动作时必须显式分层，否则必然在其中一端失真——要么对外泄漏了不该给的赔率判断，要么对内省掉了关键的失败概率。

### 通用化

任何「分析 → 决策 → 转述」的链路都适用：先问「这份输出会被谁、在什么场景下二次使用」，再决定分几层。分层的判据不是内容多少，而是**同一段文字是否存在互相冲突的使用场景**。存在冲突就必须拆，拆的依据是受众而非篇幅。

## 九、「模拟」类输出的形态约束：教练视角推演与战术板动画（2026-11-08 新增）

用户当日明确否定了此前的战术模拟交付形态：「我让你模拟是真的模拟，不是给我放几个数据。」据此重新定义该类输出的最小完备结构。

### 定义：什么才算「模拟」

战术模拟不是概率表的另一种排版，而是**双方主教练视角的约束推演**：各自的处境 → 由此决定的排兵约束 → 首发与替补 → 关键对位 → 时间线剧本 → 比分。数据只作约束条件输入，不作结论输出。

反例（不达标）：罗列 λ、xG、控球率后直接给比分。
正例（达标）：先说「卡里克必须赢，所以不能收缩，代价是双后腰只能用两名组织型，等于用中场屏障换进攻」，再由这个约束推出剧本「先得分，然后守不住」。

### 结构模板

| 段落 | 必含内容 |
| --- | --- |
| ① 双方处境 | 教练压力、赛程密度、伤停名单、必须赢/可以接受平局的处境差 |
| ② 排兵约束 | 由处境倒推的硬约束（哪些位置无人可用、哪个取舍无法回避） |
| ③ 首发与替补 | 完整 11 人 + 关键替补，**每条附理由**，并标注确认度 |
| ④ 胜负手 | 「漏洞对漏洞」的对位分析，指出最可能爆的单点 |
| ⑤ 剧本与比分 | 分时段叙事（0–30′ / 30–60′ / 60′+）+ 主推比分 + 备选比分 |

### 三个强制标注

1. **唯一变量**：把「能改变比分的那个不确定项」显式标出并给概率。例：万-比萨卡赛前评估（60% 出场）→ 出场则 1-1/1-2，缺阵则曼联左路被打穿、1-0/2-1 权重上升。
2. **口径来源**：首发为「四家媒体预测口径汇总」，非官方名单；临场 60 分钟 confirmed XI 公布后需说明如何调整 λ（本例：万-比萨卡确认缺阵 → 曼联 λ 上调、维拉下调）。
3. **结论与方向表的一致性**：当个人判断比发布值更激进时须明说。例：方向表给「胜/平」是跟市场，但私下判断偏维拉——分歧场必须让用户看见分歧本身，而不是藏在混合权重里。

### 战术板动画的交付规格

将上述推演转成可播放的可视化时，采用以下规格（已验证可交付、可直接外发）：

- **单文件 HTML，零外部依赖**：CSS/JS 内联，无 CDN、无图片外链，发给任何人双击即开；
- **分阶段推进**：12 个阶段，每段 2.5 秒自动推进，含播放控制；
- **三要素同屏**：时间线、场上球员位置（按阵型坐标布点）、比分牌；比分牌随阶段联动更新；
- **文案与数据同源**：动画中的球员名、比分、事件时间必须与文字推演完全一致，且**生成后做一次全文人名核验**（本例检查错误归属球员出现次数为 0）。

### 数据严谨性五条硬标准

由「恩佐归属」事故直接催生，适用于所有输出（含动画、海报、报告）：

1. 球员所属球队、教练归属必须核对**当期**状态，不采信跨窗旧记忆；
2. 无可靠出处的内容**整句删除**，不用「据悉/大概」等模糊说法带过；
3. 译名统一用主流中文源标准译名；
4. 数据口径必须标注（联赛 / 各项赛事、初盘 / 临场、去水前 / 去水后）；
5. 交付前做一次**人名归属自检**（逐个球员核对现属球队），作为发布前固定检查项。

> 与《偏差清单》第十四节的关系：那一节讲「为什么会错」，本节讲「错了之后输出形态该怎么定」。两条合起来构成一条纪律——**没有核实过的数据宁可不出现**。
