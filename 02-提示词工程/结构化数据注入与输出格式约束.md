# 结构化数据注入与输出格式约束

## 场景背景

一个开源紫微斗数项目（Next.js）排盘引擎完整，但**后端 AI 解读路由未开源**（README 明确说明「开源版不含 `/api/interpret`，需要你自己实现」），且商业版的「13 主题断语库、上万行」与解读 prompt 均闭源，`db-analysis.ts` 中的 `STAR_DB` 是空对象。

目标：在不复制断语库的前提下，让模型给出可用的解读。

## 核心结论：注入结构化数据，而不是注入断语

**做法**：把命盘对象全量转成结构化文本喂给模型，而不是让它背断语。

注入内容（`chart-text.ts`）：

- 命籍信息：出生时间、性别、阴阳、五行局
- 命局：命宫、身宫落点
- 十二宫：每宫主星 + **亮度（庙旺利陷）+ 四化 + 宫干自化 + 借星**
- 大限序列：各限区间、宫位、大限四化

**效果对比**：

| 方式 | 结果 |
| --- | --- |
| 靠模型记忆断语 | 泛泛而谈、套话，无法对应具体盘面 |
| 全量注入结构化数据 + 判断规则 | 输出能与盘面逐项对应（命宫贪狼旺守子、身宫落夫妻宫廉贞天府、大限三方会照官禄七杀地劫），可核验 |

数据许可提示：断语库本身受非商用条款约束，绕过它既有工程原因也有合规原因（见「数据许可与内容合规红线」）。

## 系统提示词的三层结构

1. **角色与体系**：明确以特定流派（本例为倪海厦体系）为判断框架，避免模型自行混合流派导致口径不一。
2. **判断规则**：把体系中的关键推理规则写成显式条目——三方四正如何会照、四化飞星如何作用、宫干自化如何读、空宫如何借星。规则让模型「按方法推理」而非「凭语感组句」。
3. **输出约束（OUTPUT_RULES）**：独立成节，便于单独迭代。

提示词实测长度约 1389 字——足够表达规则，又不至于挤占盘面数据的上下文预算。

## 输出格式约束必须跟渲染层能力对齐

实测踩坑：模型默认输出 Markdown（`**加粗**`、`#` 标题），而前端面板按纯文本渲染，界面上会直接出现一排星号。

**规则**：输出约束由渲染层的实际渲染能力决定，不由「希望内容好看」决定。

- 纯文本渲染 → 明确禁止 `**`、`#`、列表符号，改用【】做段落分隔（如【命格定调】【当前大限 36-45 田宅】）
- 支持 Markdown 的渲染层 → 再放开格式

这条约束写在 `OUTPUT_RULES` 里，改完热更新即生效，无需改前端。

## 流式接口与提示词的配合

- 接口：`POST /api/interpret`，请求体 `{chart, messages}`，响应为 SSE，逐行 `data: {"delta":{"text":"..."}}`，以 `[DONE]` 结尾。
- 提示词设计要假设**流式**：首段必须能独立成句（用户先看到的是前 20 字），避免"综上所述""首先"这类必须依赖下文的开头。
- 前端零改动即可接入——它本来就在等这两个路由（`/api/interpret`、`/api/heming`）。

## 已知局限（须写进产品预期）

- 格局判断、四化影响、大限走势这类**基于数据推理**的内容质量较好。
- 具体到某颗星的**古籍原话式断语**偏弱，属于模型自行组织的语言——这是因为断语库闭源，不是 prompt 能弥补的部分。
- 改进路径：积累用户反馈案例做 few-shot，逐步弥补；对应「04 数据集与评测」的案例沉淀。

## 可复用清单

1. 数据优先于语料：能结构化的领域数据全量注入，胜过让模型背结论。
2. 判断规则显式写：把领域方法论翻译成条目，避免模型用通用语感替代专业推理。
3. 输出格式由渲染层倒推，写死在独立规则块里。
4. 提示词要为流式输出设计段落级可读性。
5. 明确写出「模型做不到的部分」，避免用户用商业版预期衡量开源实现。

## 六、「独立第二意见」的 prompt 设计与审计假阳性（2026-11-03 新增）

### 场景

让外部 LLM（DeepSeek）做「方法论独立的第二意见」时，最大的敌人不是它答错，而是**伪独立**——它被喂了主模型的路径（xG、泊松、市场赔率），输出自然趋同，事后无法区分「两个模型都看到了」与「一个模型被另一个锚定」。

### 解法：prompt 主动「自废武功」

给独立第二意见的材料，必须先把主模型的路径堵死：

1. **数据段只给与主模型路径无关的原始事实**：进球/失球、主客拆分、近 5 场比分——一个 xG 数字都不给。
2. **明令禁止主模型的方法**：禁 xG、禁泊松（含双变量泊松、Dixon-Coles 等变体，防止换名绕过）。
3. **不给市场赔率**：防止锚定市场价（实测 codex 在可联网时全篇唯一数字就是市场去水值）。
4. **强制自报 `method_used` 字段**：让模型自己声明用了什么路径，供审计比对。

### 审计端的假阳性踩坑（重要）

为独立输出配了自动化审计（扫描其输出有无偷用主模型路径、λ 是否与概率自洽、概率和是否为 1）。首跑即出假阳性：

- **禁令原话被当成污染**：prompt 里写了「禁止使用 xG、泊松」，污染扫描把这句**禁令本身**命中为「使用了泊松」。弱预言检测同样命中禁令原话。
- **修正**：污染扫描只扫模型的**实际陈述**（跳过 prompt 文本本身）；弱预言检测只看模型给出的预言字段，不扫全文。

**通用规则**：凡是在 prompt 里写「不要做 X」的约束，下游任何对 X 的检测都必须先排除 prompt 文本，否则禁令越显眼、假阳性越稳定。

### 输出格式的固定化（用户消费侧约束）

高频重复任务（每场赛事预测）确定固定输出模板后，沉淀为长期规则而不是每次口头约定：

> 每场输出：方向（胜平负）1–2 个 + 让球推荐 1 个 + 比分 2 个，逐项标注信心等级（高/中/低）。

**规则**：用户确认过的输出格式应写入记忆/规则库，之后同类任务直接按模板输出，不再重新协商格式。
