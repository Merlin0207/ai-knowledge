# AI 知识库搭建记录

## 1. 目标与架构

建立一套可持续沉淀 AI 相关知识的双轨结构：

```
WorkBuddy 资料库（日常编辑、语义检索、对话内问答）
        ↕ 同步
GitHub 仓库（标准 Markdown、版本管理、跨工具复用）
```

选择双轨而非单一存储的原因：

| 需求 | 资料库 | GitHub 仓库 |
| --- | --- | --- |
| 对话内语义检索 | ✅ 原生支持 | ❌ |
| 版本历史与差异对比 | ❌ | ✅ |
| 被其他 AI 工具读取（Cursor / Dify / RAGFlow） | ❌ 无开放 API | ✅ 标准 Markdown |
| 离线可用 | ⚠️ 依赖客户端 | ✅ 本地 clone |

## 2. 目录设计

按「知识生命周期」而非「工具名」分层，五个目录覆盖从模型认知到落地与合规的完整链路：

- `01-模型与能力`：模型清单、参数规格、能力边界、选型结论
- `02-提示词工程`：模板、少样本示例、调优记录、失败复盘
- `03-应用与工程`：RAG、Agent、微调等落地实践与部署配置
- `04-数据集与评测`：数据字典、清洗规则、指标定义、对比实验
- `05-政策与合规`：监管要求、内容安全、数据合规

设计约束：

1. 目录层数不超过一层子分类，避免检索时路径过深导致归类犹豫。
2. 同一主题优先扩充已有文档，不新建碎片文件。
3. 每篇文档头部统一标注主题、来源、整理日期、适用版本。

## 3. 自动归档机制

配置了每日 22:00 触发的定时任务，将当日对话中可复用的结论整理入对应目录。

规则要点：

- 只保留可复用结论、技术决策、方法步骤、踩坑根因、数据指标
- 不复述寒暄、过程性试错、临时状态
- 按主题自动分流，归档后更新索引文档
- 当日无有效内容则跳过，不产生空文档

## 4. 踩坑记录：GitHub 连接器权限

### 现象

| 操作 | 结果 |
| --- | --- |
| `get_me` 查询身份 | 成功，返回 `Merlin0207` |
| 读取公开仓库 `octocat/Hello-World` | 成功 |
| 读取自有私有仓库 `Merlin0207/ai-knowledge` | 404 |
| 通过接口创建仓库 | 403 `Resource not accessible by integration` |

### 根因

两点叠加：

1. 连接器使用受限范围的集成令牌，只覆盖公开仓库，不含私有仓库读写权限。
2. 该授权模式下，新建仓库不会自动纳入授权集合。GitHub 对无权限的私有仓库统一返回 404 而非 403，以避免泄露仓库存在性，因此「404」不能直接推断为「仓库不存在」。

### 排查方法

用公开仓库做对照实验，是区分「令牌失效」与「权限范围不足」最快的手段：

- 公开仓库能读 → 令牌有效，问题在范围
- 公开仓库也读不了 → 令牌本身失效

### 结论的修正

仓库改为 Public 后，**读取**立即恢复；但**写入**仍返回 `403 Resource not accessible by integration`。
说明集成令牌只有 `public_repo` 级别的读权限，不含 `repo` 写权限。

因此最终采用本地 Git 推送：仓库公开后，本地凭据管理器中的 GitHub 账号可直接 push，绕开连接器的写权限限制。

### 三种通道的适用范围

| 通道 | 读 | 写 | 适用场景 |
| --- | --- | --- | --- |
| 连接器（集成令牌） | ✅ 公开仓库 | ❌ 403 | 只做检索、核对远端文件 |
| 本地 Git + 凭据管理器 | ✅ | ✅ | 批量写入、提交历史完整 |
| fine-grained PAT | ✅ | ✅ | 需要私有仓库且要自动化时 |
