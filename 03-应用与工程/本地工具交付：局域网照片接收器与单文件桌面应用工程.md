> 主题：本机自用工具的交付工程：局域网服务、单文件桌面应用与快捷方式\
> 来源：与 WorkBuddy 的对话整理（2026-11-16 两个独立需求：手机→电脑局域网传图、桌面备忘录）\
> 整理日期：2026-11-16\
> 适用版本：Windows 11 + Python 3.13.14（WorkBuddy vendor python）+ Microsoft Edge；纯标准库实现，无第三方依赖

## 结论摘要

1. **「手机传图到电脑」不必装 App**：手机自带浏览器直传 + 纯标准库 `http.server` 接收器即可，10 分钟级交付，且可固定访问码长期使用。
2. **能长期跑的关键不是脚本，而是启动方式**：会话级后台进程约 17 小时后必然退出，必须改为 `.bat` 独立窗口 + 启动文件夹自启。
3. **本机防火墙规则绑定的是解释器路径**，不是端口号——用错解释器启动，服务在本地可用、局域网不可用，且没有任何报错。
4. **零依赖单文件 HTML + Edge `--app`** 是桌面小工具的最低成本路线；`localStorage` 足够承载千级条目，不需要数据库。
5. **手写 `.lnk` 有硬性结构要求**：缺 `LinkTargetIDList` 的 `.lnk` 会被 Windows Shell 拒绝执行（返回 5 / 拒绝访问），必须用 `ILCreateFromPathW` 生成合法 ITEMIDLIST。

## 一、方案选型：局域网传图的四条路

| 方案 | 手机端成本 | 电脑端成本 | 判定 |
| --- | --- | --- | --- |
| 微信/QQ 文件传输助手 | 需装 App | 需装 App、有压缩与隐私暴露 | 用户明确排除 |
| LocalSend / KDE Connect | 需装 App | 需装 App | 体验最好，但违背「不装第三方」 |
| SMB 文件共享 | 需文件管理器支持 SMB | 需开共享、建账号、配权限 | 配置面过大，家庭网络易失败 |
| 手机端 FTP/WebDAV 服务器 | 需装 App | 需 FTP 客户端 | 反向方案，手机耗电 |
| **浏览器直传 + 本机 HTTP 接收器** | **零安装** | 一个脚本 | 采用 |

选型依据：需求是「一次性、偶发、图片为主」，不需要设备发现、断点续传、多端同步；把复杂度留在电脑侧（可控）比留在手机侧（不可控）划算。

## 二、接收器实现要点（`lan_photo_receiver.py`）

- **只用标准库**：`http.server.ThreadingHTTPServer` + 手写 `multipart/form-data` 解析（`iter_parts` 按 boundary 切分、`read_filename` 提取 `filename="..."`），不引入 Flask/第三方。
- **访问码**：6 位随机码，字母表 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（剔除易混的 I/O/0/1），比较用 `secrets.compare_digest` 防时序侧信道；`--pin` 固定、`--no-pin` 关闭（仅限完全可信私有网络）。访问码走查询参数 `?k=`，不落日志。
- **文件名消毒**：`safe_name()` 去掉路径分隔符与 `..`，只取 basename；同名不覆盖，追加序号。
- **大小上限**：单文件 100 MB、单请求 500 MB，超限返回 413 并给出中文原因。
- **类型白名单**：仅接受图片扩展名，非图片跳过并在结果里列出。
- **目录默认值**：`DEFAULT_SAVE_DIR` 写死业务目录（本次为 `D:\李梦雨\铭达劳保\未处理图片`），`--dir` 可临时覆盖；目录创建失败打印原因并返回非零退出码。
- **接口**：`GET /` 上传页、`GET /health` 健康检查、`POST /` 上传；全部返回 JSON 便于脚本断言。

## 三、网络与防火墙：本次最有价值的三条运维事实

1. **地址识别要过滤三类非可用地址**：`169.254.*`（APIPA，未拿到 DHCP）、`100.64.*`（CGNAT / 虚拟网卡）、非 RFC1918 的全部排除。`local_ipv4()` 只返回 RFC1918 私网地址，控制台区分「手机打开」与「备用地址」，避免把无效地址给用户。
2. **防火墙入站规则绑定的是程序路径，不是端口**。本机已存在名为 `Python` 的入站允许规则（Private/Public、Allow），但它绑定的程序是 `C:\Users\16974\AppData\Local\Programs\WorkBuddy\resources\vendor\python\python.exe`。因此：
   - 用该解释器启动 → 局域网可访问、无需管理员权限；
   - 用 `C:\Users\16974\.workbuddy\binaries\python\...` 启动 → 本地 `127.0.0.1` 正常、**手机访问被静默拦截**，无任何报错。
   - 启动命令固化为：`PYTHONIOENCODING=utf-8 "<vendor python 绝对路径>" -u lan_photo_receiver.py --pin <码>`。
3. **本机 curl 会走系统代理**：访问 `http://192.168.31.109:8000` 经代理返回 **502**，误判为服务故障。验证要么用 `127.0.0.1`，要么显式禁用代理（`ProxyHandler({})`）。手机直连不经代理，不受影响——这条差异是「本机测不通但手机正常」的根因。
4. 网络配置文件为 Private 是前提；Public 配置下即便有规则也会被拦（本次未触发，记录为待验项）。

## 四、让它活过 17 小时：常驻运行的三层改造

- **现象**：19:43 用户反馈手机打不开。排查：8000 端口无监听、无 python 进程、会话后台任务记录消失；IP 未变、WLAN 仍 Private、防火墙规则仍有效、目标目录已有 37 个文件（说明此前传输成功）。**根因是会话级后台进程随会话结束被回收**，不是脚本或网络问题。
- **改造一**：新增 `--pin`，访问码固定后链接可长期收藏（`http://<ip>:8000/?k=<码>`）。
- **改造二**：新增 `start_photo_receiver.bat`（纯 ASCII + CRLF、自带端口占用检测），双击脱离会话独立运行；端口已占用时只打印当前链接并退出，不覆盖已有实例。
- **改造三**：登录自启。`WScript.Shell` COM 创建快捷方式被安全策略拦截，改用**纯文件复制**：把 `start_photo_receiver.bat` 复制到 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\`，下次登录自动运行，删除该文件即撤销。
- **验证**：上传 200 且落盘、`/health` 200、上传页 200、错误访问码 403、路径穿越文件名被规范化、非图片被跳过。

## 五、桌面小工具：MemoDesk 的技术选型

- **形态**：单文件 `MemoDesk.html`（62 KB，内联 CSS/JS，零外部请求）+ `Launch.bat` + 图标 + 快捷方式。用 Edge `--app="file:///..."` 起独立窗口，无地址栏、无标签栏，观感接近原生应用。
- **为什么不做 Electron / PyInstaller**：两者都要装构建链、产物体积 100 MB 级、升级路径复杂；单文件 HTML 改一行即生效，`localStorage` 足够。
- **数据层**：`localStorage` key `memodesk.items.v1`，配 JSON / CSV 导入导出做备份与迁移；字段为事项 / 时间 / 进度 / 备注，外加优先级、标签、置顶、重复事项（完成后自动生成下一期）、到期提醒、回收站与删除撤销。
- **验证手段**（无 GUI 会话下的可复用组合）：
  1. 内联 JS 用 `node --check` 抽出来做语法校验；
  2. Edge 无头截图确认渲染；
  3. 通过 CDP（Node 22 全局 `WebSocket`）跑交互测试，本次 21 项全部通过（新建、四字段落盘、进度滑块、勾选完成、搜索、视图筛选、删除撤销、主题切换、重复生成、刷新后持久化）。
- **约束**：Bash 会话启动的 GUI 进程不显示在用户交互桌面，因此所有 UI 结论只能靠「截图 + CDP 断言」取证，不能靠「窗口是否出现」。

## 六、手写 `.lnk`（MS-SHLLINK）：三条硬结构要求

背景：环境禁止 `New-Object -ComObject WScript.Shell`，只能自己拼二进制。

1. **必须包含 `LinkTargetIDList`**，并置 `HasLinkTargetIDList`（0x1）标志位。只有 `LinkInfo` 而没有 IDList 的 `.lnk`，Windows Shell 会直接拒绝执行——`ShellExecute` 返回 **5（ERROR_ACCESS_DENIED）**，表现为「双击无反应，且无任何提示」，极易误判为权限问题。
2. **ITEMIDLIST 必须由系统 API 生成**：`shell32.ILCreateFromPathW(target)` 取合法 PIDL，再取出其字节写入；手写 ITEMID 结构在 Win11 上不稳定。
3. **无卷标盘的 `LinkInfo` 字段**：`VolumeIDSize = 20`、`VolumeLabelOffset = 0x14`；路径按 ANSI + Unicode 双写，`LocalBasePathOffsetUnicode` 必须正确回填。
4. **验证方式**：`ShellExecuteW` 返回码（本次补上 IDList 后为 **42**，成功）+ `.lnk` 二进制回读（校验 header size、标志位、IDList 长度）+ 目标程序截图，三者同时成立才算交付。
5. 落地为 `CreateShortcut.py`（纯标准库、无 COM、自动定位目录、可复现），`CreateShortcut.ps1`（COM 版）保留为其他环境的备选。

## 七、环境限制清单（本机实测）

| 限制 | 表现 | 绕法 |
| --- | --- | --- |
| PowerShell 禁 `New-Object -ComObject WScript.Shell` | 创建快捷方式直接报错 | 手写 `.lnk`（见第六节）或直接复制文件到 Startup |
| PowerShell/Bash 禁调用 `cmd.exe` | `.bat` 无法被执行测试 | 只做静态校验（ASCII/CRLF）+ 逻辑核对，交付时说明未实测 |
| Bash 启动的 GUI 进程不进入交互桌面 | 截图/窗口不可见 | headless 截图 + CDP 断言 + 返回码取证 |
| 无 `qrcode` / `PIL` | 无法生成二维码图片 | 内联 CDN `qrcodejs` 在页面渲染，URL 不上传第三方；CDN 不可用时退回手动输入地址 |
| 后台进程随会话回收 | 服务约 17 小时后静默消失 | `.bat` 独立窗口 + 启动文件夹自启 |

## 可复用清单

- 局域网小工具：标准库 HTTP + 访问码 + 路径穿越消毒 + 双上限 + `/health`，一小时内可交付。
- 交付前先确认「防火墙规则绑定的解释器路径」，否则会得到「本地通、手机不通」的假故障。
- 本机验证一律避开系统代理（`ProxyHandler({})` 或 `127.0.0.1`）。
- 需要常驻就必须脱离会话：`.bat` + Startup 文件夹复制，是零权限、可撤销的最稳方案。
- 手写 `.lnk` 先保证 `HasLinkTargetIDList`，再用 `ShellExecute` 返回码验收。
