# 视频剪辑自动化：ffmpeg 渲染管线与剪映草稿工程生成

## 结论摘要

Agent 无桌面 GUI 操作能力，不能「坐在剪映里剪」，但可行路径是**「程序化成片 MP4 + 剪映草稿工程 + 分镜时间码表」三件套交付**：命令行渲染直接出可播放成片，剪映草稿（本地 JSON）供用户在客户端打开逐段精修，时间码表兜底（草稿打不开也能照表重搭）。风格质量的分水岭不在技术而在**参考片量化拆解**：把目标风格的色彩、镜头时长、字幕密度量成数字再动手，凭感觉做出来的第一版必被批为「汇报片」。

## 一、能力边界（先说清能做什么）

**可做**：按时间码裁剪、拼接、变速、转码压缩、字幕/水印、音轨提取替换、抽帧、色彩还原与调色（LUT）、程序化配乐合成——一切能用脚本明确描述的确定性剪辑。

**不可做**：可视化时间线交互、逐帧审片卡点、精细调色的主观迭代、读写剪映/Premiere/达芬奇私有工程之外的格式转换、代用户操作 GUI（拖拽、实时预览）。

**AI 视频生成**（文生视频/图生视频）属于生成新素材，不是剪辑，另为一类。

## 二、工具链与职责切分

| 脚本 | 职责 | 关键点 |
| --- | --- | --- |
| `analyze_footage.py` | 素材盘点：时长/分辨率/编码/像素格式/色彩倾向/帧率，等间隔抽帧生成带标注联系表 | 抽帧判读是「根据素材剪」的技术前提；时长需微秒（剪映用） |
| `render_film.py --render` | 按分镜表渲染成片：裁剪、竖屏铺满、调色、转场、字幕、混音 | 支持只重渲指定镜头，不必全量重跑 |
| `render_film.py --check` | 渲染前校验：入出点越界、素材路径有效性 | 试渲染必须先跑；短片段入点越界要自动前移 |
| `make_score.py --duration N` | 按成片时长合成原创配乐 | 能量曲线留白+高潮；RMS/峰值自检（RMS≈0.11 垫底水平、峰值<0.8 无削波） |
| `attach_music.py` | 独立换音轨：不重渲画面，几十秒完成 | 自动无缝铺满（接缝 1.5s 交叉淡化）、淡入淡出、归一化、同步剪映草稿 |

环境：本机 PATH 无 ffmpeg 时先装静态版；换配乐必须做成独立工具——音乐来源会反复换（合成曲/剪映曲库/用户文件），画面不该陪着重渲。

## 三、素材判读：两个实测教训

### 3.1 设备与编码实测（大疆 OsmoAction 5 Pro，车载机位）

153 段 / 132 GB / 5.52 小时，横屏 108 + 竖屏 45；原片 2688×1512、HEVC 10bit、59.94fps、bt709。**bt709 非 Log，不需要 LUT 还原**——先读色彩标签再决定是否做 D-Log/HLG 还原，别按「大疆=Log」的预设走。`E:\DCIM\DJI_001` 里 MP4 旁的 LRF 是代理文件，不进时间线。

### 3.2 长片段只抽两帧会判读偏

成片抽查发现标注「渐暗公路」的收尾镜头实际是**车里躺着睡觉的人**——长片段（数十秒）只抽入点附近两帧，画面内容判读偏了。修法：37 镜头逐段多帧抽验；车载机位在动，单帧稳定不代表整段稳定，要扫整段找「全程都稳」的区间。

### 3.3 救不回来的镜头直接删

两段竖拍的峡谷夹缝素材，横屏铺满后必然是大面积灰白天空+车窗边框，怎么调入点都救不回来。连同灰雾镜头一起删除：37→34 镜头、2:55→2:22。**「只留能打的画面」优先于凑时长。**

## 四、风格定位：从「汇报片」到「片子」

第一版被用户四条批评否决，全部成立：

| 批评 | 根因 | 改法 |
| --- | --- | --- |
| 时间性太强 | 片头标题、章节字幕（一·穿过戈壁…）、日期、片尾总结句——是汇报结构不是片子 | 全片零字幕；不按行程叙事，按「颜色→光→山→人→路→落日」情绪组接；只留首尾淡黑 |
| 竖屏不能留模糊边 | 模糊铺底是偷懒方案 | **放大铺满 + 偏上裁切**，山、湖、栏杆等主体保留，冲击力反而更强 |
| 颜色没调 | v1 盐湖段饱和度仅 0.176（灰绿一片） | 自研 3D LUT：轻对比不压暗、冷色推青绿/暖色推金黄、灰白天空补青蓝、暗角、微锐化；盐湖 0.153→0.267、日出 0.306→0.555、荒漠 0.277→0.447 |
| 配乐空缺 | 「先出无配乐版」不是可交付状态 | 配乐与画面同期交付，缺曲先合成原创垫底 |

### 参考片量化拆解法（核心方法）

用户发来参考视频后，先拆成数字再动手，不凭感觉：

- 结构：无标题、无章节、无日期，只有底部极小字；镜头 4–6 秒硬切；
- 色彩：浓烈青绿天空 + 暖黄大地、高饱和、暗部占比近 0（白天段通透明亮，不能一味压暗）、暗角；
- 音乐：有明显留白与高潮的能量曲线，不是平铺。

第一版压暗过头、盐湖绿得发荧光，就是因为只看了「暗调」没量化「暗部占比≈0」。**调色先在单帧上 A/B 验证（饱和度等指标前后对比），确认方向再整片重渲。**

## 五、剪映草稿工程生成

### 5.1 格式要点

- Windows 端草稿 = `draft_content.json` + `draft_meta_info.json`，位于 `AppData\Local\JianyingPro\User Data\Projects\com.lveditor.draft\<草稿名>\`；
- `materials`（素材库）与 `tracks`（轨道）解耦引用；时间单位**微秒**；画幅由 `canvas_config` 定义；
- 可用开源库生成；生成后校验素材路径全部有效、轨道段数与时长一致。

### 5.2 风险控制：最小草稿先验证

草稿是私有格式、随版本变化，`draft_meta_info.json` 还记录导入过的素材；本机无现成草稿可对照版本时，**先生成一份最小草稿让用户点开确认能进时间线，再填完整内容**。若版本不兼容，成片 MP4 与分镜时间码表不受影响——三件套互为兜底。

### 5.3 草稿引用「成品片段」而非原片

v2 改版后草稿若还引用原片，用户在剪映里看到的就和成片不一致。**草稿引用调色后、竖屏已铺满的成品片段**，打开即所见成片效果，可直接逐段微调。改版时成片与草稿必须同步更新（同一个管线步骤，不要分两次跑）。

## 六、配乐工程

- **合成配乐**：按目标时长生成，能量曲线对齐参考片（留白+高潮），自检无削波、RMS 量级合理；
- **时长偏差**：片段实际时长比标称多几十毫秒，配乐会略短于画面——音频自动补尾，避免收尾被截；
- **换曲工具化**：`attach_music.py` 只替换音轨（无缝铺满、交叉淡化、归一化、同步草稿），换任何曲子几十秒，不重渲画面。

## 七、外部曲库抓取的工程细节与许可

- 剪映曲库本地无音频缓存（详见 05 文档第七节），外部曲库用 curl 抓直链可行：Bensound `travel-nature / ambient` 分类抓到 174 条直链、11 首下载解码验证；
- **许可三硬要求**（Free Music 标记、唯一署名码、禁改）不满足时只能作风格试听，不进交付。

## 八、通用坑

1. **requests 与 curl 同站返回不同内容**：站点按客户端（UA/指纹）返回不同页面，Python 抓不到的先用 curl 落地再解析；
2. **shell 内联正则会被转义吃掉**（反斜杠、冒号）：改用独立脚本文件，避开转义；
3. **Python 长网络请求会挂住**：改 curl + 短超时走全程；
4. **后台渲染任务完成后必须抽查成片**（抽帧核画面、验音轨、查字幕残留），「exit code 0」不等于内容正确——本轮收尾镜头错配就是靠抽查而非日志发现的；
5. 用户对成片的批评按条记录并逐条改，**先修不依赖参考素材的硬伤，不等素材到位**。
