# 数据许可与内容合规红线

## 一、开源项目的三层许可必须分开看

以紫微斗数项目为例，一个仓库里可能同时存在三种授权，**代码许可不代表数据许可**：

| 对象 | 许可 | 约束 |
| --- | --- | --- |
| 代码 | MIT | 可自由使用、修改、分发，须保留版权声明 |
| 数据集 | CC BY 4.0 | 可商用，**须署名** |
| 作者原话 / 断语内容 | **非商用** | 仅限个人使用，不得用于商业产品 |

**实操结论**：自己看盘、内部研究无碍；一旦要做成对外产品，第三条是硬约束，必须先取得授权或替换内容源。这也是技术选型时需要先查许可、再决定是否复用其语料的原因——闭源断语库既构成工程障碍，也构成合规风险。

## 二、公开代码仓库的内容红线

仓库从 Private 改为 Public 是不可逆操作：任何人与爬虫都能读取、clone、被搜索引擎收录，**已扩散的内容无法收回**。

**绝对不得写入**：

- API Key、access token、账号密码
- 客户信息、个人身份信息
- 内部系统地址、内网域名
- 未公开的商业数据、合同条款

**推荐写入**：方法论、口径定义、架构决策、排障根因、脱敏后的指标与算例。

判断标准：假设这段文字明天出现在搜索结果第一位，是否仍然可以接受。

需要存放敏感内容时，正确做法是新建私有副本仓库，或为敏感部分单独建私有仓库并用 fine-grained PAT 推送，而不是"临时放一下再删"。

## 三、密钥管理

| 做法 | 结论 |
| --- | --- |
| 写入 `.env.local` 并在 `.gitignore` 中配置 `.env*` | ✅ 推荐 |
| 通过对话把密钥发给工具 | ⚠️ 会进入对话记录与云端存档，仅在你接受该风险时使用 |
| 把密钥写进代码或提交进仓库 | ❌ 绝对禁止 |
| 密钥按最小权限签发（fine-grained PAT，仅单仓库 Contents 读写） | ✅ 推荐 |

更稳妥的流程：密钥由本人本地填写，工具只负责重启服务与验证链路，不接触密钥原文。用完的临时凭据（验证脚本、测试文件、临时环境变量）应显式清理。

## 四、AI 输出涉及博彩/概率预测时的表述红线

这类输出的合规风险不在"是否预测"，而在**是否构成投注建议**。

| 禁止 | 替代做法 |
| --- | --- |
| "稳胆""必中""跟着买" | 给出概率与区间，并标注失败概率 |
| 单一确定结论 | 同时给出保本门槛与期望值，说明"不划算"也是结论 |
| 隐去不确定性 | 显式写明"未计入红牌/点球扰动"等未建模变量 |
| 面向不特定公众的下注引导 | 限定为方法讨论与概率参考 |

实测中形成的表述范式：

> 该场我算 52.5%、市场 47.0%，差 5.5pp，但落在自身敏感性区间内，判定为噪声，**不给方向**。三项的保本门槛我全算了一遍，主胜 EV −6.8pp、客胜 −5.7pp、让球上盘 −0.3pp，全部负期望。

这种"算出不划算所以不碰"的结论，比方向命中更值得沉淀——它只依赖定价，不依赖运气。

## 五、第三方内容引用的边界

- 引用他人预测（博主、模型、平台）时，须区分**事实**与**观点**：事实错误要纠正并标注来源，观点分歧只做记录，不做对错判定。
- 未证实的传闻（"某队内讧""某球员被罚下"）不得作为模型输入，只能标为「待验证」。
- 开源项目二次开发时保留原作者版权声明与项目名，README 中说明改动范围。

## 六、一句话检查清单

1. 这段内容属于代码、数据还是文本？各自许可是否允许当前用途？
2. 仓库是公开的吗？里面有没有密钥或可识别个人的信息？
3. 输出会不会被读者当成投注/医疗/法律等专业建议？
4. 引用的事实有官方来源吗？没有的话标注了吗？

## 七、外部音乐素材与平台曲库的许可边界（2026-11-10 新增）

背景：为旅游视频找「可商用」配乐时的三条路径实测——平台曲库程序化获取、第三方免版税曲库直链抓取、程序合成原创配乐。

### 7.1 平台曲库（剪映）无法程序化获取，且联网与否无关

- 剪映客户端在跑、确实在联网（下载过字体与资源库），但整个 `User Data` 目录递归扫描 **0 个音频文件**：`Cache/audioWave/*.waveDataV2` 只是画时间线波形的可视化数据，不是声音；`Cache/ressdk_db/*/rp.db` 存的是特效/贴纸/分类元数据。
- 曲库属于客户端私有接口：账号 token + 设备签名 + 客户端内鉴权，入口在 GUI 里。**「客户端在线」和「能被程序调用」是两回事**，联网解决不了通道问题。
- 可行路径：用户在剪映曲库里点选/试听后音频文件落到本机，程序再扫描接入。**「可商用」标签的实际价值是平台自动识别时避免侵权限流，授权由曲库覆盖，比自己找的第三方曲子干净。**

### 7.2 第三方免版税曲库：抓得到 ≠ 可发布

以 Bensound 为例，免费许可有三个硬要求：

1. 只覆盖标记 "Free Music" 的曲目；
2. 视频简介须粘贴**下载时给的唯一署名文本 + license code**（一视频一码）——页面直链抓取拿不到署名码；
3. **不允许剪辑或修改曲目**——循环拼接、淡入淡出都属于修改。

结论：直链抓到的曲子**只能当风格试听，不能直接发布**。署名与禁改条款往往比「商用与否」更严格，与商业用途无关也要核对。

### 7.3 程序合成原创配乐是零顾虑替代

按目标时长合成氛围配乐（pad 和弦 + 低频 + 铃音，按参考片能量曲线做留白与高潮），自检 RMS、峰值无削波。不是有旋律的流行曲——与用户期待可能有落差，须提前声明；版权上比任何第三方曲子都干净。

### 7.4 处置原则

许可核对的检查顺序：曲目是否有 Free/可商用标记 → 署名要求（唯一码？文本格式？）→ 是否允许剪辑修改 → 分发平台是否额外要求。**任何一条不满足就降级为「风格试听」，并在交付时明确说清，不默认用户接受风险。**
